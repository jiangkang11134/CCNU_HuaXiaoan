# 记忆抽取技能

本文件是记忆抽取的**唯一口径来源**，同时服务两个读者：

- **人 / Agent**：读「一、机制」「二、事实键」「三、服务端的闸」「五、怎么用」「六、怎么改」，理解平台记住了什么、为什么某条没生效、改动该落在哪里。
- **抽取模型**：只读「四、抽取规范」那一段。它由一对 prompt 标记包起来（HTML 注释形式，本文件里各只出现一次），
  加载时按标记截取，作为抽取调用的 system prompt 主体（见 `yuxi/memory/extraction.py` 的 `build_system_prompt`）。
  标记不符合「恰好各一次」就整段作废、退回内置兜底 prompt，并打 WARNING。

抽取**不是**在回答链路里做的：回答照常流式返回，流结束后由后台任务
`extract_turn_memory`（ARQ，见 `services/run_worker.py`）单独调一次模型。
接受「事实晚一轮生效」的延迟，换来回答链路不掺抽取纪律、抽取失败不毁掉已生成的回答。

## 一、这套机制在做什么

关于用户的信息分成两个容器。生命周期、作用域、覆盖方式都不同，**不要混用**：

| | 会话事实 `session_facts` | 长期记忆 `user_memory_facts` |
|---|---|---|
| 事实键前缀 | `project.*` | `user.*` |
| 作用域 | 仅当前会话 | 跨会话，仅本人，绝不共享 |
| 有效期 | 2 天 TTL | **分键**：多数长期有效，`user.research_direction` 30 天、`user.work_environment` 7 天；**再次提及即续期** |
| 出生状态 | `observed` → `active`（同一事务内） | `candidate`，或直接 `confirmed` |
| 覆盖 | 内容变了则旧条 `superseded` | 已 `confirmed` 的不被低置信度覆盖 |
| 是否注入回答 | 是（`active` 且未过期） | **只有 `confirmed` 才注入** |
| 权威性 | 用于个性化、指代消歧、检索提示 | 同左 |

两边的硬边界（设计文档已定，不得突破）：

- **结论依据的三级优先级**（用户明确口径，不得颠倒）：
  1. **已批准并重新入库的修正**——问题反馈 → 管理员审批通过 → 重新入库的知识块（注入为 `[权威修正]`）
  2. **知识库 / Graph RAG 的可追溯证据**
  3. **个人记忆与偏好**（注入为 `[当前可用事实]`）——只用于个性化，**不作任何结论依据**
- 记忆**不得作为实验室安全规范、化学品性质或合规结论的证据**。
  `MemoryService.build_context` 会在注入文本里写明**完整三级排序**，不能只写「以知识库为准」——
  那样与 `[权威修正]` 段里「与知识库冲突时以修正为准」合起来是**残缺的排序**，
  模型会误以为知识库是最高权威，而第一优先级其实是管理员批准的修正。
- 表达层（怎么说话）、检索层（先查什么）可以个性化；**结论层（安全规范、相容性禁忌、合规判定）禁止个性化**。因此 `user.response_preference` 只能影响措辞，绝不能影响安全口径。

## 二、白名单事实键

键的集合是封闭的，唯一定义在 `yuxi/memory/observation.py:MEMORY_FACT_KEYS`。
模型自创的键会被 `normalize_op` 拦掉并计入 `dropped_ops`。

长期记忆（`user.*`，进 `user_memory_facts`）：

- `user.major` —— 专业／学科背景。正例：「我是化学工程专业的」。反例：某次问到的实验原理。
- `user.education_stage` —— 学历／培养阶段。正例：「我在读本科二年级」。反例：课程作业的截止日期。
- `user.research_direction` —— 研究方向／在做的课题。正例：「我们组做锂电正极材料」。反例：本次问的单个化学品的闪点。**有效期 30 天。**
- `user.work_environment` —— **长期所处的实验／工作环境**（场所、实验室类型、常驻单位或院系）。
  正例：「未来很大一段时间我都将待在生化化学实验室」「我常驻逸夫楼的危化品实验室」。
  反例：「我们实验室没有通风橱」（那是本次的操作约束，走 `project.constraints`）、
  「这周三在三楼做实验」（临时安排）。**有效期 7 天。**
- `user.lab_role` —— 实验室角色。正例：「我是实验室安全员」「我带本科生的实验课」。反例：临时帮同学代做。
- `user.response_preference` —— 回答形式偏好。正例：「回答简短点，别列长清单」「多用表格」「以后直接给结论」。反例：对某次回答内容的评价（那属于反馈，不属于偏好）。

会话事实（`project.*`，进 `session_facts`）：

- `project.current_goal` —— 当前会话要达成的目标。正例：「这次是想把危化品台账整理出来」。
- `project.phase_scope` —— 本次只做哪一块。正例：「先只看第 3 章，别扩展到全篇」。
- `project.constraints` —— 本次必须遵守的约束。正例：「只讨论常温常压条件」「我们的实验室没有通风橱」。
- `project.acceptance_criteria` —— 什么样算做完／做对。正例：「最后要能直接贴进安全培训材料」。
- `project.rejected_approach` —— 用户已明确否决的方案。正例：「不要用 PPR 那种推导过程，太绕了」。

**「长期待在哪」与「那里的临时条件」要分开**（2026-09-20 新增 `user.work_environment`）：
用户说"未来很大一段时间我都将待在生化化学实验室"，这是跨会话画像，落 `user.work_environment`；
而「我们实验室没有通风橱」这类**设备与操作条件**仍只落 `project.constraints`（**仅本次会话有效**）——
它随时可能因为换实验室、换通风橱而失效，而系统拿不到任何"条件变了"的信号。
仍然**不能靠把 `project.*` 当长期记忆用**：`project.*` 的语义就是"本会话有效"，
当跨会话画像用会让下个会话继承上个会话的临时约束——那正是「方向对穿」。

**置信度直接决定能否生效**（`observation.arbitrate`）：`user.*` 且置信度 ≥ `0.85` 才落 `confirmed`，才会被注入下一轮回答；低于 0.85 落 `candidate`，而候选态目前没有前端确认入口——**置信度给低了，这条记忆就等于没记**。因此用户明确陈述的给 0.9 以上，只在字里行间推断的给 0.5~0.7。

## 三、服务端的闸（LLM 只能提议）

三道校验都在服务端，prompt 可以搬位置，闸门不能搬位置：

1. **白名单** `MEMORY_FACT_KEYS`：键不在表内 → 丢弃。
2. **敏感信息** `SENSITIVE_PATTERN`：命中身份证／手机号／电话／邮箱／住址／银行卡／密码／api key／secret → 丢弃。
3. **状态裁决** `arbitrate`：决定 `confirmed` / `candidate` / `rejected`。

另外两条容易被误以为"模型说了算"、实际不是的规则：

- **通道由 key 前缀裁定**，不采信模型填的 `channel`（`canonical_channel`）。模型填错不会出错，只会被计入 `channel_mismatch` 埋点。让模型自由选通道会重现"方向对穿"：偏好写进会话事实表、会话事实写进长期记忆表。
- **状态机** `state_machine.py`：状态只能由后端改。会话事实 `observed → active`；长期记忆 `candidate → confirmed` 等。非法跃迁直接抛错。

## 四、抽取规范

<!-- prompt:start -->
你是对话记忆抽取器。给你一段用户与助手的多轮问答，以及系统当前已记录的事实，
你的任务是判断这段对话里出现了哪些**值得长期留存**的信息。

只输出 JSON，不要任何解释、不要 markdown 代码块：
{"ops": [{"turn": 2, "fact_key": "user.major", "content": "化学工程", "confidence": 0.95}]}

字段约束：

- `fact_key` 只能取以下之一，不在其中的一律不要输出：
  - 长期画像（跨会话）：user.major（专业）、user.education_stage（学历阶段）、
    user.research_direction（研究方向／在做的课题）、user.work_environment（长期所处的
    实验／工作环境，即"长期待在哪个实验室、哪个院系"）、user.lab_role（实验室角色）、
    user.response_preference（回答形式偏好，如"要简短""多用表格"）
  - 会话约束（仅本次会话）：project.current_goal（本次目标）、project.phase_scope（本次范围）、
    project.constraints（本次约束，如"没有通风橱""只讨论常温常压"）、
    project.acceptance_criteria（验收标准）、project.rejected_approach（已否决的方案）
- **别把"待在哪儿"记成研究方向**：「未来很大一段时间我都将待在生化化学实验室」讲的是
  所处环境，抽 `user.work_environment`，不是 `user.research_direction`；
  反过来「我们组做锂电正极材料」才是 `user.research_direction`。两者可以同时存在。
- `channel`：`memory` 表示跨会话画像，`session` 表示只在当前会话有效。
  系统会按 `fact_key` 复核这一项，填错不会出错，但填对更好。
- `content` 用一句话客观陈述，不超过 {limit} 字，不要带"用户说""据了解"之类前缀。
- `confidence` 是 0~1。**这一项很关键**：`user.*` 只有 ≥ 0.85 才会被系统直接确认并
  开始影响后续回答，低于 0.85 的会停在候选态、当前无人可确认，等于白记。
  所以用户明确说出的给 0.9 以上，从语气里猜的给 0.5~0.7，拿不准就别输出。
- `turn` 是这句话出现在第几轮（从 1 开始），不确定就省略。
- 信息可以跨轮拼起来（例如第 1 轮说专业、第 3 轮才补充方向），此时 `turn` 填**首次出现**的那一轮。
- 不要输出已记录事实的重复项；用户改口时输出**新值**（系统会用新值取代旧值）。
- 同一段对话里最多输出 8 条，挑最确定、最有用的。

**不要**记录（这些写了也会被系统丢弃，或者本来就不该记）：

- 实验室安全规范、化学品性质、操作步骤、法规条文——那是知识库的职责。
- 对助手某次回答的评价（"这段答得好/不好"）——那是反馈，走另一条链路。
- 一次性、瞬时性的内容：本次问的某个化学品的参数、某个日期、某句闲聊。
- 隐私信息：手机号、邮箱、身份证、住址、银行卡、密码、密钥。
- 助手自己说的话、助手的推理过程、知识库检索到的内容——只记录**用户透露的关于自己的信息**。
- 否定句里的**否定事实**：「我不做有机合成」不要记成研究方向；「这不是我要的」不要记成目标。
- 替他人转述的提问：「我同学想问…」「我们老师让我查一下」——那不是用户自己的画像，不抽。
- 假设、将来时、条件句：「以后如果要做 X」「等开学再说」——除非是明确的当前目标，否则不抽。

**判断示例**（左侧是原话，右侧是该不该抽）：

- 「我是化学工程专业大三的」→ 抽 2 条：`user.major`=化学工程（0.95）、`user.education_stage`=本科三年级（0.95）。
- 「帮我查一下丙酮的闪点」→ 不抽。这是知识库问题，不透露关于用户自己的信息。
- 「回答简短一点，别每次都列一大串」→ 抽：`user.response_preference`=偏好简短回答，不要长清单（0.9）。
- 「我们实验室没有通风橱，所以只能给常温下的操作」→ 抽：`project.constraints`=实验室无通风橱，仅讨论常温操作（0.9）。
- 「先只看第 3 章，别扩展到全篇」→ 抽：`project.phase_scope`=本次只看第 3 章（0.9）。
- 「算了，别用那种理论推导的方式，太绕了」→ 抽：`project.rejected_approach`=不要理论推导式的回答（0.85）。
- 「上次说的那个方案我再想想」→ 不抽。没有明确的新事实，且信息量为零。
- 「这段总结得不错」→ 不抽。这是对回答的评价，属于反馈。
- 「我是实验室安全员，平时负责危化品台账」→ 抽 2 条：`user.lab_role`=实验室安全员（0.95）、
  `project.current_goal`=整理危化品台账（0.85）。
- 「我们组做锂电正极材料，主要是三元材料」→ 抽：`user.research_direction`=锂电正极材料（三元材料方向）（0.9）。
- 「未来的很大一段时间，我都将待在生化化学实验室」→ 抽：`user.work_environment`=未来很长一段时间在生化化学实验室（0.9）。**不是** `user.research_direction`。
- 「邮箱是 abc@xx.com，报告发我」→ 不抽。隐私信息，系统也会丢弃。

没有值得留存的信息就输出 {"ops": []}，不要为了凑格式编造。

## 五、记忆该怎么用（回答侧）

这一节是给**回答模型**的口径，与「四」互补：「四」决定记什么，这一节决定记住之后怎么用。

### 注入长什么样

`MemoryService.build_context` 每轮把已生效的记忆拼成文本插进系统提示，形如：

```
以下内容仅用于个性化、指代消歧和检索提示，不得作为实验室安全规范、化学品性质或合规结论的证据。
结论依据的优先级：已批准并重新入库的修正 > 知识库/Graph RAG 可追溯证据 > 本段记忆与偏好。
- [session] project.constraints: 实验室无通风橱，仅讨论常温操作
- [long_term] user.major: 化学工程
```

`[session]` 只在本会话有效；`[long_term]` 是跨会话画像。**只有 `confirmed` 的长期记忆会出现**，
候选态看不到——所以不要假设"系统可能还记着别的"。

紧随其后还有一段 `[个人资料]`（`yuxi/services/user_profile.py` 拼装），只放身份、专业与回答风格：

```
以下为用户在个人资料中填写的信息，仅用于个性化、指代消歧与检索提示，不得作为……依据。
信息冲突时的优先级：本轮会话事实 > 本段个人资料 > 长期记忆中记下的同类信息。
- 身份：学生
- 专业：应用化学
```

**姓名、性别、学工号不进 prompt**——它们对回答没有帮助，只会白烧 token，要展示给人看就在前端渲染。
三段顺序是 `[当前可用事实]` → `[个人资料]` → `[权威修正]`，别调换：个人资料的风格说明要"指上文"，
而结论依据的最高层要压在最后。

### 三个允许的用途

1. **指代消歧**：「我们实验室」「我们组」「这个专业」指什么，用记忆补全，
   不要反问用户已经说过的信息。
2. **检索提示**：用专业／研究方向推断该优先查哪类资料（如「锂电正极材料」→ 优先检索电池相关规范）。
3. **表达形式个性化**：`user.response_preference` 只影响**怎么说**——长短、分点、表格、
   先给结论还是先给依据。

### 信息冲突时的三级优先级

**这条规则适用于所有个性化信息，不只是回答风格。**

> **本轮会话事实 > 个人资料 > 长期记忆中记下的同类信息**

| 层 | 来源 | 例子 |
|---|---|---|
| 最高 | 本轮会话事实 | 用户这轮说「这次简短点」「我现在做锂电」 |
| 中 | 个人资料（用户自己填的，见 `[个人资料]` 段） | 专业填了「应用化学」、风格选了「详细严密」 |
| 最低 | 长期记忆（模型从历史对话推测的） | `[long_term] user.major`、`user.response_preference` |

越靠近当下、越明确，优先级越高。冲突时按上面的顺序取，**不要折中**，
也不要因为"两处都提到了"就把两条都采纳。

**顺序不只是声明，代码里也执行了**：个人资料里有值的字段，会把它对应的长期记忆事实
从 `[当前可用事实]` 里摘掉（映射见 `services/user_profile.py:PROFILE_OVERRIDDEN_FACT_KEYS`）。
只声明不执行的话，模型会同时看到「专业：应用化学」和 `[long_term] user.major: 化学工程`
两个答案，等于把仲裁权又推回给模型——而模型没有任何依据判断该信哪个。
目前真正撞车的只有「专业」（`user.major`）；**新增会撞车的个人资料字段时必须同步那张映射表**。
注意**只摘长期记忆**：会话事实是这条规则的最高层，永远不摘。

**「正常风格」不是一种风格**：它是缺省态，不产出任何风格指令。`[个人资料]` 段在
`response_style=normal` 时只注入身份与专业，不注入风格——这样会话事实和长期记忆才有发挥空间。
把「正常」写成"请正常回答"反而会把回答压向平均值，属于负优化。

### 三条禁令

1. **不得把记忆内容当安全结论的证据**。记忆是元数据，不是知识；安全规范、化学品性质、
   相容性禁忌、合规判定一律按上面的三级优先级取依据（**修正 > 知识库 > 记忆**），
   而记忆这一级**根本不参与结论**。
2. **不得因为用户偏好而改写安全口径**。「回答简短」不代表可以省略必要的警示——
   形式可以压缩，结论不能打折。
3. **不得跨用户使用**。长期记忆按 uid 隔离，任何「别人也这样」的推断都不成立。

### 用户追问时

- 问「你记得我什么 / 你怎么知道的」：如实区分是本会话的还是长期记住的，
  并说明**它不影响安全结论**。
- 要求「忘掉 X」：那是撤回请求，走 `/api/memory` 的撤回能力；
  **不要在对话里假装已经忘了**——没落库就还会被注入。
- 记忆明显过时（「我已经不在那个组了」）：照常回答，改口会在本轮抽取里被记为新值
  （`user.*` 走 supersede；旧的不会被低置信度覆盖）。
- 问「这条会记多久」：如实说有效期——`user.research_direction` 30 天、`user.work_environment`
  7 天，**再次提到就从当天重新计时**，其余键长期有效。到期只是不再注入（状态转 `expired`），
  记录与变更历史都还在，用户仍可在「我的记忆」里看到并手动撤回。

> **注**：这一节**目前不会自动进入回答 prompt**——`build_context` 只注入事实清单和一句免责声明。
> 要让回答侧自动拿到这份口径，把上面「允许／禁止」的要点补进
> `memory/service.py:build_context` 的注入头即可。改动很小，但会影响**每一轮**的 prompt 长度，
> 属于要权衡的热路径改动，不要顺手做。

## 六、怎么改

- **调整抽取口径**（加例子、改措辞、收紧尺度）：直接改上面「四」的段落，无需发版、无需改代码。抽取调用按 (mtime, size) 判断文件是否变化，编辑后下一次抽取即生效。
- **让人 / Agent 也能查到它**：本技能由 `agents/skills/buildin/__init__.py` 注册、worker 启动时播种进技能表，但**只有把 `memory-extraction` 加进 Agent 的 skills 列表，Agent 才会在系统提示里看到它**（中间件只注入被选中的技能）。注意两件事互不影响：**这个 skill 没被任何 Agent 选中，抽取照旧按本文件运行**——抽取是平台能力，本文件是它的规格；要停抽取请用下面的 `memory_observe.enabled`。
- **增删事实键**：必须**同时**改两处——`yuxi/memory/observation.py:MEMORY_FACT_KEYS` 和本文件的「二」「四」；两者由 `test/unit/memory/test_memory_skill_guide.py` 的漂移守卫对齐，只改一处会红。
- **改有效期**：`yuxi/memory/observation.py:MEMORY_FACT_TTL_DAYS`（事实键 → 天数；**不在表里 = 不过期**），
  由 `memory_fact_ttl()` 读出。注意它**只作用于新建与续期的行**：存量行不会被回填，
  改完要么等它们自然被 supersede，要么手工补 `expires_at`。
  改完同步本文件「一」的有效期行与「二」的键说明。兜底 prompt 不用改——它只列键，不写天数。
- **只关抽取、不发版**：`SystemKV("memory_observe")` 的 `enabled` 置 false。
- **节流**（省钱）：`SystemKV("model_routing")` 的 `memory_extract_min_interval`（秒）。节流**不推进游标**，被跳过的轮次会在下次一并抽。
- **换抽取模型**：`SystemKV("model_routing")` 的 `memory_model_spec`；不配则跟随该会话正在用的模型。

## 七、出问题先看哪里

抽取是全自动的，唯一的可观测信号是 `memory_events` 里每次抽取写的计数（`extraction` / `extracted` 事件）：

- `call_failed` —— 模型调用失败。游标**不推进**，交给 ARQ 重试。
- `empty_response` —— 模型返回空。游标推进（重试无意义）。
- `parse_failed` —— 返回的不是合法 JSON（含"取第一个花括号片段"的宽容解析也失败）。
- `dropped_ops` —— 有 op 被丢弃：白名单外、命中敏感词、或超出 8 条上限。
- `channel_mismatch` —— 模型填的 `channel` 与服务端裁定的不一致（不报错，只说明模型理解偏差）。
- `rejected` —— 走到 `arbitrate` 被拒（键不在白名单）。
- `renewed` —— 同一条记忆被**再次提及**、有效期已往后推（内容没变，所以不算新建）。
  这个计数是"续期到底有没有生效"的唯一直接信号；它长期为 0 就说明用户没再提，
  那条记忆会在 TTL 到期时被 `expire_memories` 置为 `expired`。

排查顺序：先看事件计数定位是"没调起来"（`call_failed`/`throttled`）还是"调起来了但抽不出"（`empty_response`/`parse_failed`/`dropped_ops`），再确认 `UserConfig.enable_memory`（`user.*` 不落库）、`memory_observe.enabled`（整体关闭）、以及游标是否停在旧位置（`MemoryExtractCursor`，`memory/cursor.py`）。
