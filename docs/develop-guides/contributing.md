# 贡献指南

本项目按内部业务系统方式维护。提交修改前，请先确认需求来源、影响范围和验证方式。

## 开发原则

- 改动必须围绕当前业务目标。
- 保持接口契约清晰，不通过临时兜底隐藏错误。
- 前台、后台和权限相关变更需要同步验证角色差异。
- 涉及数据结构变更时，需要补充迁移或初始化说明。

## 提交流程

1. 从当前主分支创建功能分支。
2. 完成代码、文档和必要测试。
3. 运行格式化、lint、构建或对应单元测试。
4. 在提交说明中写清楚业务影响和验证结果。

## 前端验证

```bash
cd web
pnpm exec eslint <changed-files>
pnpm build
```

## 后端验证

```bash
cd backend
python -m compileall server package
```

具体测试命令按模块实际情况执行。

## 文档要求

- 用户可见流程发生变化时，需要更新对应使用说明。
- 权限、角色、部门或前后台入口变更时，需要说明业务边界。
- 不保留外部项目链接作为系统使用入口。
