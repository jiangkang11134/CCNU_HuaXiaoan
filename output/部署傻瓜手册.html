华小安（Yuxi）傻瓜式部署手册

适用对象：拿到本仓库全部文件的部署人员（已 git clone 或拷贝了整个项目文件夹）。 目标：在一台 Linux 服务器 上把整套系统跑起来，并能在浏览器访问、能对话。 写文档时对照的真实文件：docker-compose.prod.yml、scripts/deploy_prod.sh、scripts/init_prod_env.sh、.env.template、各 docker/*.Dockerfile。命令均可整段复制粘贴。

---

0. 先说结论（避免再问"docker 里怎么什么都没有"）

仓库里 docker 部署需要的文件全都在 git 里、一个不少：

docker-compose.prod.yml      # 生产编排（核心）
docker-compose.yml           # 开发编排
docker/api.Dockerfile        # 后端镜像
docker/web.Dockerfile        # 前端镜像
docker/paddlex.Dockerfile    # OCR 镜像（可选，需 GPU）
docker/mineru.Dockerfile
docker/nginx/*.conf          # 反代配置
docker/sandbox_provisioner/* # 沙箱服务镜像
docker/PP-StructureV3.yaml
.env.template                # 环境变量模板（在 git 里）
scripts/init_prod_env.sh     # 生成 .env.prod 的脚本（在 git 里）
scripts/deploy_prod.sh       # 一键部署脚本（在 git 里）

唯一故意不在 git 里的文件是 .env.prod（里面放密钥，不能进版本库）。它必须由你本地生成（见第 4 步）。所以"docker 里什么都没有"的真实含义通常是：没生成 .env.prod + 没装/启动 Docker + 没拉镜像——不是仓库缺文件。

1. 准备一台服务器

最低配置建议（跑得动 Milvus + Neo4j 这一堆）：

项目最低推荐
内存8 GB16 GB 及以上
CPU2 核4 核及以上
磁盘40 GB 可用80 GB 及以上（向量库/图库数据会增长）
系统Ubuntu 20.04/22.04 64 位Ubuntu 22.04
外网首次部署需要能联网拉镜像长期可内网

如果你服务器本身不能联网，请看文末「附录 B：完全离线部署」。绝大多数云服务器（阿里云/腾讯云/华为云）都有外网，直接用第 5 步的最简流程即可。

安全组 / 防火墙：放行 TCP 80（网页访问）。5432（PostgreSQL）默认只在容器网络内，不建议对公网开放。

2. 把代码弄到服务器上

两种方式任选其一。

方式 A：git clone（服务器能联网、且仓库对他可见）

# 在服务器上
cd /opt
git clone https://gitee.com/jiang-kang123/CCNU_HuaXiaoan.git
cd CCNU_HuaXiaoan

若仓库是私有的，把上面 URL 换成带用户名令牌的形式： git clone https://用户名:令牌@gitee.com/jiang-kang123/CCNU_HuaXiaoan.git 之后升级代码用 git pull 即可。

方式 B：直接拷文件夹（服务器不能联网，或图省事）

在本机（代码齐全的那台机器）把整个 CCNU_HuaXiaoan 文件夹打成包，传到服务器：

# 本机
cd 父目录
tar czf yuxi.tar.gz CCNU_HuaXiaoan
scp yuxi.tar.gz 用户名@服务器IP:/opt/

# 服务器
cd /opt && tar xzf yuxi.tar.gz && cd CCNU_HuaXiaoan

⚠️ 拷贝时不要漏掉隐藏文件（.env.template 不是隐藏的没问题，但 .gitignore 等无所谓）。只要 docker-compose.prod.yml、docker/ 目录、scripts/ 目录、backend/、web/ 在就行。

3. 在服务器上安装 Docker 和 Docker Compose

# 一键安装 Docker（Ubuntu）
curl -fsSL https://get.daocloud.io/docker | bash -s docker --mirror Aliyun
# 或者用官方： curl -fsSL https://get.docker.com | sh

# 启动并设为开机自启
sudo systemctl enable --now docker

# 确认版本（Docker 24+ 自带 compose 子命令）
docker --version
docker compose version

如果 docker compose version 报错，说明是老版本，需要单独装插件： sudo apt-get install -y docker-compose-plugin 本文所有命令都用 docker compose（带空格），不是老式的 docker-compose。

把当前用户加入 docker 组，免得每条命令都加 sudo（可选但推荐，做完重新登录生效）：

sudo usermod -aG docker $USER

---

4. 生成 .env.prod（最关键、最容易被漏的一步）

仓库里没有 .env.prod，必须本地生成。脚本会自动复制 .env.template 并填好密钥、实例 ID、数据目录：

# 在服务器上的项目根目录 CCNU_HuaXiaoan 里
bash scripts/init_prod_env.sh

跑完会看到：

Production env ready: .env.prod
YUXI_DATA_DIR=./docker/volumes

脚本已经帮你自动设置好了：

  • YUXI_ENV=production
  • JWT_SECRET_KEY（自动生成 32 字节随机值）
  • YUXI_INSTANCE_ID（自动生成）
  • YUXI_DATA_DIR=./docker/volumes（数据持久化目录）

4.1（强烈建议）改成生产级配置

用编辑器打开 .env.prod 改这几项（不改也能跑，但生产环境建议改）：

nano .env.prod      # 或 vim .env.prod
变量默认值建议
POSTGRES_PASSWORDpostgres改成强密码
NEO4J_PASSWORD0123456789改成强密码
MINIO_SECRET_KEYminioadmin改成强密码
YUXI_DATA_DIR./docker/volumes改成代码目录外的绝对路径，例如 /data/yuxi，避免重新拉代码时误删数据
YUXI_SUPER_ADMIN_NAME空填一个管理员账号名，首次启动会自动建号
YUXI_SUPER_ADMIN_PASSWORD空填管理员密码
HOST_IP空填服务器公网 IP（容器需要生成外链时才用）

改完 YUXI_DATA_DIR 后记得建目录并授权：mkdir -p /data/yuxi && chmod 777 /data/yuxi（或让 docker 自行创建即可）。

注意：模型供应商的 Key、OCR Key、搜索 Key 不在这里填，登录后台后在「模型供应商 / 基本设置」里配（见第 8 步）。.env.template 顶部注释也写明了这一点。

5. 拉镜像 + 构建 + 启动（核心三步）

镜像来源分两类：

  • 基础镜像（neo4j、milvus、postgres、redis、minio、etcd、nginx、python、node 等）：Docker 会自动从网上拉。
  • 本项目镜像（api、web、sandbox-provisioner，以及可选的 paddlex）：由 docker compose 现场构建（构建时需要联网装 Python/Node 依赖）。

直接一条命令搞定（在项目根目录）：

docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build

这条命令会：

  1. 拉取所有基础镜像；
  2. 构建 api、worker、web、sandbox-provisioner（首次构建较慢，10–30 分钟，取决于网速，因为要装 libreoffice、中文字体、Python 依赖、Node 依赖）；
  3. 按依赖顺序启动全部容器（postgres→redis→minio→etcd→milvus→sandbox-provisioner→api/worker→web）。

想看实时日志/进度，另开一个终端：docker compose -f docker-compose.prod.yml --env-file .env.prod logs -f 想只重建某一个：docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build api

关于 paddlex（OCR，需要 NVIDIA GPU）：默认不会启动（它在 profiles: [all] 里）。普通问答场景不需要它。如果服务器有 GPU 且要用 OCR： docker compose -f docker-compose.prod.yml --env-file .env.prod --profile all up -d --build

---

6. 验证是否真的起来了

# 看所有容器状态（STATUS 应为 Up / healthy）
docker compose -f docker-compose.prod.yml --env-file .env.prod ps

# 健康检查（返回 ok / healthy 字样即成功）
curl http://127.0.0.1/api/system/health

在你自己电脑的浏览器打开：

http://服务器公网IP/

能看到登录/首页就说明前端 + 后端 + 反代都通了。

如果网页打不开，先确认：① 服务器安全组放行了 80；② 容器 web-prod、api-prod 都是 Up；③ curl http://127.0.0.1/api/system/health 在服务器本地能通。

7. 数据初始化（首次）

首次启动后，系统会自己建库、跑迁移。无需手动操作。 如果你在第 4.1 步设了 YUXI_SUPER_ADMIN_NAME / YUXI_SUPER_ADMIN_PASSWORD，管理员账号会在初始化时自动创建；否则按页面首次注册提示创建。

---

8. 登录后台配置模型供应商（不配就不能对话）

系统能打开 ≠ 能回答问题。模型供应商没配，问答会失败。

  1. 浏览器打开 http://服务器公网IP/，用管理员账号登录。
  2. 进入后台「模型供应商」，填一家大模型供应商的：
  • base_url（接口地址）
  • api_key（密钥）
  1. 设置默认模型（聊天模型、嵌入模型等）。
  2. （可选）「基本设置」里配 MinerU（文档解析）、Tavily（联网搜索）等 Key。

⚠️ 红线提醒（来自项目规范）：模型 base_url 和 api_key 只放在模型供应商配置里，不要写进 .env.prod，也不要写进任何 model-routing / SystemKV 配置——那些地方任何登录用户都能读到，绝不能放密钥。

配完回到对话页试一句"你好"，能正常回复即部署完成。

9. 日常运维命令速查

# 停掉全部（保留数据）
docker compose -f docker-compose.prod.yml --env-file .env.prod down

# 重启
docker compose -f docker-compose.prod.yml --env-file .env.prod restart

# 看某个容器日志（如 api）
docker compose -f docker-compose.prod.yml --env-file .env.prod logs -f api

# 升级代码后重新部署（若你是 git clone 的）
git pull
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build

也可以直接跑一键脚本（它内含 init_prod_env + down + git pull + up --build + 健康检查）： bash scripts/deploy_prod.sh 注意：该脚本里有 git pull，如果你是方式 B（直接拷文件夹、没有 git remote），这步会报错中断，这种情况下请用上面手动的 up -d --build 即可。

10. 常见问题排查

Q1：构建卡在 uv sync / pnpm install 很久或失败

  • 首次构建要装大量依赖，耐心等；失败多是网络问题。服务器能联网通常 OK。
  • 若 PyPI 慢，可在 docker/api.Dockerfile 第 55 行 uv sync 后加 --index-url https://pypi.tuna.tsinghua.edu.cn/simple（脚本注释里也提了这点）。

Q2：curl http://127.0.0.1/api/system/health 一直不通

  • docker compose ... ps 看 api-prod 是否 healthy（首次启动 milvus 等要 1–2 分钟）。
  • docker compose ... logs -f api 看报错，多半是 .env.prod 里数据库密码/地址不对或依赖服务没起来。

Q3：浏览器打开是空白 / 502

  • 看 web-prod 和 api-prod 是否都 Up；nginx 反代在 docker/nginx/ 里已配好，一般无需改动。

Q4：改了 .env.prod 不生效

  • 改完必须重建相关容器：docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build api worker，或直接 down 再 up -d --build。

Q5：数据库/向量库数据在哪

  • 都在 YUXI_DATA_DIR 下（默认 ./docker/volumes，建议已改到 /data/yuxi）。备份整个目录即可。

附录 B：完全离线部署（服务器不能联网）

思路：在一台能联网的机器上把镜像全部准备好，导出成 tar，拷到服务器再导入。

# === 在能联网的机器（项目根目录）===
# 1) 先构建 + 拉取所有镜像
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
# 2) 导出 compose 涉及的全部镜像为一个 tar
docker save $(docker compose -f docker-compose.prod.yml --env-file .env.prod images -q | sort -u) -o yuxi_images.tar
# 3) 把 yuxi_images.tar 和项目文件夹一起拷到服务器

# === 在服务器（项目根目录）===
docker load -i yuxi_images.tar
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d   # 注意：离线就别加 --build 了，镜像已就绪

离线时 up 不要带 --build，否则它会尝试重新构建并报网络错误。镜像已经 load 进来了，直接 up -d 即可。 注：仓库自带的 scripts/save_docker_images.sh 只导出基础镜像列表（不含本项目自定义镜像），上面用 compose images -q 的方式更全，推荐用上面这条。
